# project-folder-init - 标准项目文件夹初始化

**版本**: 1.3
**规范底稿**: `{WORKSPACE}/1、项目/readme/资料/项目文档规范-搭建方法.md`
**运营框架**: `{WORKSPACE}/1、项目/readme/运营框架-三文档联动.md`
**流程唯一事实来源**: `{WORKSPACE}/1、项目/readme/goal.md`（项目启动六步法 + 细分流程，本 skill 必须与其对应）
**样板项目**: `{WORKSPACE}/1、项目/2026年6月市场营销外呼的是是什么用户/`（2026-09-24 起根目录仅保留分类目录；项目说明在 `00_项目说明\`，看板在 `01_进展看板\`）

## 何时使用

- ✅ 用户说「新建项目文件夹」「初始化项目」「给 XX 项目起个脚手架」
- ✅ 新开一个需要 goal / To-Do / 看板 / PRD 跟进的项目
- ❌ 已有项目文件夹只想补单个文档 → 直接复制对应模板文件，不必整套生成

## 输入

最少只需两项：

1. **项目名**：用作文件夹名，简洁直接（如「2026年8月门店外呼对账」）。
2. **一句话目标**：写进 goal.md 核心目标与 To-Do 文档头部。

可选：关联待办工具任务名/ID、关键信息来源（会议纪要路径）、初始任务清单。
3. **项目类型**：默认「通用项目」；若用户要做汇报 / 分析报告（说「做报告」「出汇报」「建汇报项目文件夹」或内容明显是取数分析汇报），选「汇报项目」，走下方变体模板。

## 标准结构（固定，不得增删根级文件）

```
<项目文件夹>/
├── goal.md            # 项目目标与交付标准（唯一事实来源）
├── To-Do 文档.md      # 任务清单（唯一事实来源，看板数据以它为准）
├── 进展看板.html      # 交互式看板（展示层，单文件零依赖）
├── PRD-进展看板.md    # 看板需求文档（功能编号 + 实现状态）
├── 任务状态.json      # 看板配套状态文件（供「导入 JSON」）
└── 资料文件夹/        # 会议纪要、数据源等原始材料
```

> **6 个根级交付物**之外，模板另含 **2 个运行辅助文件**（非根级交付物，生成时保留）：
> - `server.py`：看板「保存当前」写回 任务状态.json 所需本地服务。**必须先运行 `python server.py`，再用浏览器打开 `http://localhost:8765/进展看板.html`**；直接双击 file:// 打开仅能看/拖，写回会失败。
> - `script\`：辅助脚本目录。

## 变体：汇报项目文件夹（汇报标准流程 TWK034）

> 当项目本质是「做汇报 / 分析报告」（走 `report-doc-standard-workflow` 七步流程）时，不用上面的通用脚手架，改用变体模板 `templates\汇报项目文件夹\`。落位与通用项目一致：`{WORKSPACE}/1、项目/<项目名>/`（一个事情一个文件夹）；另在 `{WORKSPACE}/汇报文档/` 建 `<项目名>.lnk` 快捷方式指向它作汇报索引。

```
<汇报项目文件夹>/
├── 汇报大纲.md        # S1-S3：背景 / 最终要回答的问题 / 核心假设（唯一事实来源）
├── 数据BRD.md         # S4：取数需求（表头、来源、拼表键），用户确认后才取数
├── 产出数据/          # S5
│   ├── <最终>.xlsx    # 根目录只放最终 Excel
│   ├── 过程数据/      # 过程 CSV / JSON / 中间 Excel 统一放这里
│   └── Script/        # 取数与处理脚本
├── set/               # 配套汇报素材（截图、配图等；配图为可选项）
├── 汇报.html          # S6 产出，生成时创建
├── 汇报大纲PPT        # S6 产出，生成时创建
└── 配套文档/          # S6 分析过程子文档（协作平台版落汇报知识库后本地归档）
```

- 通用脚手架的 goal.md / To-Do / 看板在汇报项目中**默认不生成**；该项目同时需要看板管理时再按需补充并说明。
- `汇报.html` 与 `汇报大纲PPT` 是 S6 产物，初始化时不预生成空文件。
- 占位符替换（`{{项目名}}` / `{{日期}}` / `{{问题1}}` / `{{假设1}}` 等）、index.md 登记、自检、回报与通用流程一致。
- 报告结构本身套 `business-report-structure`（背景→问题→假设→论据→总结→backup，配图可选）。
- **快捷方式索引**：创建后建 `{WORKSPACE}/汇报文档/<项目名>.lnk` → 项目文件夹；S7 归位时再由 `report-doc-standard-workflow` 补 `{WORKSPACE}/data/汇报数据沉淀/<项目名>产出数据.lnk` → `产出数据\`。快捷方式用 `WScript.Shell` COM 创建。

## 执行步骤

1. **确认输入**：项目名 + 一句话目标；若用户没给初始任务，先用 2-3 条占位任务，提示用户后续补充。
2. **确定落地路径**：通用项目与汇报项目都默认 `{WORKSPACE}/1、项目/<项目名>/`；目标文件夹已存在则先停下询问，禁止覆盖。
3. **复制模板**：通用项目复制 `templates\标准项目文件夹\`；汇报项目复制 `templates\汇报项目文件夹\`（保留子目录）。
4. **替换占位符**（全部文件，替换后 `Select-String '{{'` 计数应为 0）：
   - `{{项目名}}` → 项目名；`{{日期}}` → 当天日期（YYYY-MM-DD）
   - `{{一句话目标}}` / `{{推进路径}}` / `{{信息来源}}` → 按输入填写，没给的写「待补充」
   - `{{project_key}}` → 项目名的英文/拼音小写下划线形式（用于看板 localStorage key，如 `store_outbound_check`）
   - 任务类：`{{最终交付任务}}`/`{{最终交付任务名}}`、`{{支撑任务1}}`/`{{支撑任务2}}`、`{{支撑任务1的目标}}`/`{{支撑任务2的目标}}`、`{{动词短语：干什么}}`、`{{解决什么问题；若是其他任务的前置，在此注明}}`、`{{姓名}}` → 按初始任务清单填写；**先按定稿任务清单更新 To-Do 表格（唯一事实来源），再同步镜像到 任务状态.json 与看板 DATA**，保持三处 id/名称一致
   - 目标类：`{{最终目标}}`、`{{最终目标一句话（项目最终交付物）}}`、`{{最终产出形态}}`、`{{验收条件}}`、`{{会议纪要 / 原始资料，存入 资料文件夹/}}` → 按 goal.md 填写
   - ⚠️ 语义：看板 DATA 的 **id0 总目标节点 = 项目最终交付物（非任务）**；任务状态.json 与 To-Do 只列任务，不列 id0
5. **初始化原则**：
   - To-Do 表格固定 5 列：# / 任务名 / 达到的目标 / 负责人 / 备注（状态符号写备注列）。
   - 状态图例固定：⏳ 待推动 / 🔄 推动中 / ✅ 已完成 / 🚫 不需要。
   - 完成标记：任务名删除线 `~~任务名~~`（首选）+ 状态列 ✅，手动维护。
   - goal.md 按待办工具任务规范的 7 要素写：核心目标 / 主要问题 / 要做什么 / 交付物 / 交付标准 / 关键信息来源，表述简洁。
6. **登记到项目状态索引（必做）**：在 `{WORKSPACE}/1、项目/index.md` 追加一行（项目名 / 文件夹 / 状态 🔄 / 关联待办工具任务 / 建档日期），并补待办工具任务关联：
   - 若该项目有对应待办工具清单任务，把任务名 + 链接填进该行；没有则先标「待关联」，同步去待办工具确认/建单后补填。
   - 登记后再进入六步法后续推进。
7. **创建后自检（必做）**：
   - [ ] 根级条目齐全：通用项目 = 6 个交付物（goal.md / To-Do 文档.md / 进展看板.html / PRD-进展看板.md / 任务状态.json / 资料文件夹）+ script/ + server.py；汇报项目 = 汇报大纲.md / 数据BRD.md / 产出数据（含 过程数据、Script）/ set / 配套文档
   - [ ] 全部文件无残留 `{{ }}` 占位符（用 `Select-String -Pattern '{{' -Recurse` 检查）
   - [ ] 看板 DATA 与 To-Do 表格、任务状态.json 的任务 id/名称一致
   - [ ] 已在 `{WORKSPACE}/1、项目/index.md` 登记一行
   - [ ] 浏览器打开 进展看板.html 能正常渲染（可选，有浏览器环境时做）
8. **回报**：给出文件夹路径、文件清单、下一步建议（补任务清单、把会议纪要放进资料文件夹）。

## 项目推进六步法（与 README goal.md 严格对应）

> 生成脚手架只是**第 1 步**。脚手架落地后，按 `{WORKSPACE}/1、项目/readme/goal.md` 的六步法推进，**每步确认后再进下一步**：

| # | 步骤 | 产出物 | 确认闸门 |
|---|------|--------|---------|
| 1 | 创建 Goal 文件夹 + goal.md | 项目文件夹 + goal.md | 目标与交付标准初步对齐 |
| 2 | 基于 goal.md 探讨清楚目标 | 锁定版核心目标（结论先行） | 你确认目标后才进 To-Do |
| 3 | 探讨 To-Do List | 5 列清单（拆解遵循下方「To-Do 拆解指引」） | 你确认清单后才做看板 |
| 4 | 制作看板 | 进展看板.html + 任务状态.json（绑定） | 渲染与状态核对通过 |
| 5 | 有产品化需求 → 撰写 PRD | PRD-进展看板.md | PRD 确认后才开发 |
| 6 | 资料进资料文件夹 | 归档 + goal.md 关键信息来源登记 | 收尾确认 |

### To-Do 拆解指引（第 3 步专用）

- **先评估**：这条任务是否含「做产品 / 做网页 / 取数」之类的事。
- **若含 → 合并成一条，不拆成两条**：任务名直接写「创建 PRD + 取数」这类合并表述（如「创建取数 PRD + 取数」是一条，不写成「先写 PRD」+「再取数」两条）。PRD 是前置动作，不是独立交付物。
- **拆分判定**：只有多产出物且拆开能加快进度才拆，参考 `task-analyzer`（效率优先 / 前置优先 / 合并相关 / 内聚不拆，子任务带五要素）。

## 细分流程速查（与 README goal.md 对应）

- **文档编辑**：先写大纲 → 确认 → 明确重点；结论先行（`business-report-structure`）；分析类先定假设再取数。
- **取数**：先做表探测确认（对每张表抽样看字段/格式、验证可取出性与拼表键，出「字段确认清单」交用户，确认的才写），再写取数 PRD/BRD（① 数据来源与表头 ② 字段映射 ③ 时间范围与拼表逻辑），**确认后才取数**；SQL 用 `sql-development` 写、DIP（`dip-query-service`）执行；取数 PRD 与 SQL 均带版本号。
- **会话分工**：一个任务一个窗口，窗口命名 `[项目名] 环节`（如 `[外呼核查] 取数BRD`）；新窗口带旧窗口产物链接；需求增改回对应 BRD/PRD 窗口讨论确认后再开发。

## 运营规则速查（详见运营框架文档）

- **To-Do 文档.md 是唯一事实来源**：改任务状态只改这里，再手工同步看板 DATA 与 任务状态.json。
- **进展看板.html 是展示层**：只负责看和交互，不当记录源。
- **PRD-进展看板.md**：看板功能变更时更新需求表与实现状态（✅/⏳/🔄）。
- **维护分工**：To-Do 与 PRD 由主 Agent 维护；HTML 由开发 Agent 修改。
- **资料文件夹**：会议纪要、原始数据一律放这里，不散落根目录。

## 可选：Spec 模式规格文档（.trae/specs/ 等）

> 与上文脚手架文档体系**正交，不互相替代**。本小节只适用于「用带 Spec 模式的编码工具（如 Trae）做单个功能需求设计」的项目，可选、非强制。

- **触发方式**：用 Spec 模式为一个功能做设计时，工具会自动在 `.trae/specs/<功能名>/` 等目录生成 `spec.md` / `tasks.md` / `checklist.md`，与脚手架的 `goal.md` / `To-Do 文档.md` **不同层、不冲突**：脚手架管「项目级目标 + 任务看板」（goal/To-Do 唯一事实来源），spec 管「单个功能的需求契约」。
- **四文件定位**：
  | 文件 | 角色 | 收尾去留 |
  |:---|:---|:---|
  | `goal.md` | 项目目标 + 验收总纲 | 一直保留 |
  | `spec.md` | **需求契约主文档**：What 变更 + 原由 + ADDED/MODIFIED/REMOVED + 每个 Requirement 的 WHEN/THEN 验收场景 | 一直保留 |
  | `tasks.md` | 实施步骤（Task/SubTask + 依赖） | 交付后删/归档 |
  | `checklist.md` | 从 spec 验收点抽出的「打勾便签」 | 交付后删/归档 |
- **关键认知**：`spec.md` 不是单纯验收清单——除验收 Scenario 外还含 Why / What / Impact / 变更记录，是「需求定义 + 验收标准」的**契约主文档**；`checklist.md` 只是它的打勾影子，**不算重复**。
- **瘦身建议**：执行期四个都在；**交付收尾后只留 `goal.md` + `spec.md`**，删掉 `tasks.md` / `checklist.md`（或把实施/验收并进 `执行计划.md`）。

## 注意事项

- 看板模板已内置四态（⏳ 待推动 / ✅ 完成 / ⏸ 等待 / 🚫 不需要）、树状布局、连线、拖拽、聚焦、导入 JSON，**不要**为样式重写整个 HTML，只改 DATA / GROUPS / 标题 / localStorage key。
- 项目名含中文时 `{{project_key}}` 必须转英文/拼音，避免 localStorage key 异常。
- 生成后若用户提供了会议纪要，移动到 `资料文件夹\` 并在 goal.md「关键信息来源」登记。
