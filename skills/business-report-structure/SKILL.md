# 汇报大纲结构（v3：结构路由层）

## 核心定位

管汇报文档「按什么逻辑展开」。v3 起，本 skill 不只提供单一分析型大纲，而是先判断汇报场景，再路由到对应模板。

```
全链路  report-doc-standard-workflow（背景→问题→假设→数据BRD→Excel→报告→文件管理）
结构层  本 skill（先选模板，再定大纲）          ← 你在这里（对应全链路 S6）
风格层  document-writing（每段怎么写得好）
实例层  weekly-briefing / mtd-achievement-review（具体业务固定模板）
```

## 使用场景

- 要写汇报/报告，不确定「怎么展开」——先在这选结构模板
- 汇报场景不同：常规进展/分析（分析型） vs 高层、时间紧、要拍板（决策版）
- 汇报写完自查：按对应模板检核清单过一遍
- 全链路生产（背景→报告→文件归位）走 report-doc-standard-workflow；本 skill 是其 S6 环节

## 模板路由（先做这一步）

| 判断条件 | 使用模板 | 结果形态 |
|---|---|---|
| 读者是高层 / 时间紧 / 需要当场拍板 / 明确有是/否、A/B、预算、时间类决策 | **决策版汇报**（见下） | 决策点 + 方案总览 + 论证 + 方案 + 投入产出 + 回扣决策 |
| 只是分析原因、解释现象、汇报进展，不要求当场决策 | **分析型汇报**（沿用 v2 大纲） | 背景 → 问题 → 假设 → 论据 → 总结 → backup |
| 已有报告要自查质量 | 先判断原报告类型，再跑对应模板的 checklist | 检核结果 + 修改指令 |
| 不确定选哪版 | 默认用分析型；若开头能明确写出 1~3 个决策点，切决策版 | 避免把普通分析硬包装成决策汇报 |

路由原则：**先问“读者要做什么”，再选结构。** 不要所有汇报都用决策版，也不要把需要拍板的内容写成分析长文。

## 模板一：分析型汇报（默认）

适用：不需要当场决策的分析、复盘、进展汇报。

| 节 | 内容 | 核心问题 | 必写？ |
|---|---|---|---|
| **1 背景** | 为什么做、给谁看 | “为什么有这份汇报？” | 是 |
| **2 最终要回答的问题** | 列出 1~3 个问题；不清晰先确认，不硬编 | “要回答什么？” | 是 |
| **3 核心假设** | 预估答案，按假设方向组织证据 | “我猜答案是什么？” | 是 |
| **4 论据** | 以小主题呈现：**小主题结论 + 支撑数据**（数据来自 S5 Excel，禁编造） | “证据呢？” | 是 |
| **5 总结** | 收束回答第 2 步的问题 | “所以答案是什么？” | 是 |
| **6 backup** | Excel 里内容多但正文没用上的，以「结论 + 论据」小主题形式放文末大 backup 里 | “还有哪些备查？” | 否 |
| **附 配套文档** | 报告的产生与分析过程，作为子文档（协作平台文档）放汇报知识库 | “细节在哪？” | 否（用户要求时） |

## 模板二：决策版汇报（高层 / 时间紧 / 要拍板）

详细底稿：`references\决策版汇报框架_v1.md`

### 结构

| 节 | 内容 | 核心问题 |
|---|---|---|
| **1 一句话结论 + 决策点** | 先给结论；列 1~3 个可用是/否、A/B、金额、时间回答的决策点 | “要批什么？” |
| **2 方案总览** | 背景、方案、收益、投入、决策点 | “3 分钟能看懂吗？” |
| **3 为什么要现在做** | 现象（有数据）→ 影响（有业务后果）→ 根因（分客观环境 / 机制问题） | “为什么现在？” |
| **4 方案内容** | 每个动作：对象、动作、目标、责任方、完成时间 | “做什么？” |
| **5 投入与产出** | 投入、短期产出、中期产出、风险、退出机制 | “值不值？做不好怎么办？” |
| **6 建议与决策请求** | 回扣开头决策点，明确建议顺序 | “现在确认什么？” |
| **附 数据口径说明** | 分析宇宙、时间窗、去重粒度、状态优先级、数据来源 | “数字怎么来的？” |

### 硬规则

1. **决策先行不等于删证据**：总览只负责快速决策，正文必须保留关键数据链；压缩只能删推导和重复，不能删证据
2. **开头结尾都要有决策点**：禁止“请审阅”“请指导”
3. **每个动作五要素**：对象、动作、目标、责任方、完成时间
4. **必须有 HOW MUCH**：投入、产出、风险、退出机制；金额类风险写上限或区间
5. **关键指标先定口径**：分析宇宙、时间窗、去重粒度、状态优先级；总数必须能分解到子项
6. **检核输出可执行**：问题定位、当前状态、修改建议、需要数据、通过标准，缺一不可

## 通用硬规则（两套模板都适用）

- **最小篇幅**：只保留能回答核心问题的内容，答不出的论据小主题直接删
- **重点高亮**：定稿后重点数字做的好标绿、不好标红；修订 / 待确认内容先标黄，黄色优先级高于绿色和红色
- **数据口径放最后附录**：数据来源 / 口径 / 周期放文末，不在正文前堆口径
  - ⚠️ **周期例外（2026-10-12）**：「数据周期」必须显眼——文档开头标题下方固定一行 `**数据周期：YYYY-MM-DD ~ YYYY-MM-DD**`，每个数据块下方另标一次；全篇周期须一致（跨周期对比需事先经用户确认且在开头写明）。正本见 `report-doc-standard-workflow\references\协作平台文档数据呈现标准_v1.md`，交付前跑 `scripts\check_doc_period.py`。放文末的只保留「来源 / 取数方法 / 筛选条件 / 分子分母定义」。
- **空壳章节不交付**：未填实的占位章节直接不写
- **不写「局限」章节**：风险融入正文对应结论处一句话说明
- **素材按需**：不为丰富而堆砌图表
- **假设可被数据迭代**：发现新假设或推翻原假设，先回写假设清单，再补数据验证
- **数据底线**：关键结论至少一组数据支撑；关键表上方必须有一句结论

## 决策版 11+1 检核清单

1. 开头和结尾是否写了决策点？
2. 是否有方案总览？3 分钟内能否看懂现象、根因、方案、收益、决策点？
3. 小标题是否直接写结论？
4. 关键部分是否 MECE？用了哪种拆解方法？
5. 是否定量定性结合？
6. 是否覆盖内部和外部视角？
7. 颜色、单位、小数位、来源、文案是否一致？长文案是否有 2-8 字摘要？
8. 每个关键结论是否有数据支撑？每张关键表是否有一句结论？
9. 是否说明投入、产出、风险、边界、退出机制？
10. 决策人是否还会问“你的建议是什么”？
11. 关键指标是否写清分析宇宙、去重粒度、状态优先级，并做总数/子项对齐？

+1 会后复盘：YES（认可什么）/ NO（调整什么）/ MORE（追问什么）

## 审核输出标准

检核已有汇报时，不能只输出「通过 / 不通过」。每条问题必须包含：问题定位、当前状态、修改建议、需要数据、通过标准。输出还必须包含推荐结构、修改清单、可直接执行的修改指令、重跑验收标准。

## 使用流程

0. **先查实践库**：读 `{WORKSPACE}/Knowledge/practice/index/practice-index.json`，按本次汇报场景匹配实践卡（结构 / 口径 / 呈现类），命中的闸门逐条勾；卡见 `practice-library` skill
1. 接到汇报任务 → 先判断读者任务：要拍板还是要理解
2. 要拍板 / 高层 / 时间紧 → 决策版；只需要理解分析 → 分析型
3. 按所选模板定大纲，不直接开写
4. 问题、假设、决策点不清晰 → 先列「待确认清单」，不硬编
5. 每个论据或动作自检：结论 / 决策价值 + 数据支撑，缺一不写
6. 产出 md + html；协作平台版创建前须用户确认
7. 文档修改走协作平台评论；改完回「✅已修改」

- [ ] backup 只放正文没用上的内容吗？
- [ ] 决策版：开头结尾有决策点吗？有投入产出和退出机制吗？指标口径对齐了吗？
