# 定性分析方法

## 适用场景

汇报需要回答「为什么」：用户 / 一线 / 管理者怎么看、为什么反对、核心诉求是什么。用于补充定量数据无法解释的动机、感知和顾虑。

## 输入

- 必需：访谈记录、调研反馈、会议讨论、用户原话
- 建议：反馈人角色、场景、时间、是否受方案影响

## 执行流程

1. **统一口径**
   - 先定义每个反馈问题的对象、场景、时间范围
   - 若不同渠道问法不一致，分开归组，不直接合并结论
2. **提取原话**
   - 每条反馈保留一句能代表观点的原话
   - 去掉情绪化表达，但不改变原意
3. **观点归类**
   - 先按「支持 / 反对 / 中性」分组
   - 再按诉求维度二次归类：收益预期、执行成本、风险担心、公平性、边界场景
4. **挖原因**
   - 对每类观点追问「为什么」，归到 3 层：
     - 表层：说了什么
     - 动机：担心什么 / 想得到什么
     - 机制：现有规则或信息差导致的根因
5. **收敛共性**
   - 只保留能影响决策的诉求；孤立的个人偏好放 backup
   - 明确「反对比例不高但影响关键决策」的意见，不能被比例淹没
6. **形成结论**
   - 每条定性结论写成：**结论 + 支撑原话 + 对方案的影响**
   - 若结论影响方案设计，写清需要补的条款或测算

## 输出格式

| 结论 | 支撑原话摘要 | 诉求 / 根因 | 对方案的影响 | 样本说明 |
|---|---|---|---|---|

## 判断标准

- **可进正文**：影响方案设计、预算、风险边界、推进节奏
- **放 backup**：有参考价值但不改变决策
- **不进文档**：无法核实、与决策无关、只有情绪没有诉求

## 质量检核

- [ ] 是否先统一了调研口径，再合并结论？
- [ ] 每条定性结论是否都有原话支撑？
- [ ] 是否挖到了「为什么」，而不是只统计支持 / 反对比例？
- [ ] 是否说明了样本范围和局限位置（放在对应结论处，不单开局限章节）？
- [ ] 是否把关键反对意见映射到了方案条款？

## 敏感信息处理

- 引用原话时去掉人名、工号、可识别的团队信息
- 不保留内部调研原始表；只沉淀归类方法和脱敏结论
