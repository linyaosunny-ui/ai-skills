# 指标口径校验方法

## 适用场景

汇报中出现状态、流向、转化、覆盖范围、预算等关键指标，或多个来源给出不同数字时使用。

## 输入

- 必需：指标名称、当前数字、来源 SQL / 表 / 文档
- 建议：原始明细、历史版本、相关指标的分项数据

## 执行流程

1. **定分析宇宙**
   - 写清对象、时间窗、排除条件
   - 示例：某车型 8/1 后成交且 9/17 前退订完成的用户，一人一状态
2. **定去重粒度**
   - 明确按人、订单还是记录汇总
   - 一人多单时，先定优先级规则，再汇总
3. **定优先级规则**
   - 状态类指标必须写清判断顺序
   - 示例：后续订单状态 > 退订后工单状态 > 未知
4. **做并集校验**
   - “新订单”类指标 = 新成交 ∪ 新交付，不能只取其中一个子集
   - 一个人同时有新成交和新交付时，按更高完成度状态归类，不能重复计数
5. **交叉复核**
   - 同一指标至少用两种路径重算
   - 总数必须可分解到子项，子项相加必须等于总数
6. **差异归因**
   - 两口径数字不一致时，先解释差异来自哪里
   - 常见原因：漏并集、漏子项、去重粒度不同、快照时点不同、优先级规则不同
7. **落文档**
   - 正文只保留一个主口径
   - 若确需保留另一个口径，命名区分并写明用途，不能混排在同一列

## 输出格式

| 指标 | 口径定义 | 主口径结果 | 复核口径结果 | 差异原因 | 采用口径 |
|---|---|---|---|---|---|

## 质量检核

- [ ] 分析宇宙、时间窗、排除条件是否写清？
- [ ] 去重粒度是否明确？
- [ ] 状态优先级规则是否明确？
- [ ] 是否做了并集校验？
- [ ] 总数和子项是否能相加对齐？
- [ ] 两口径差异是否已解释？
- [ ] 正文是否只使用一个主口径？

## 敏感信息处理

- 不在通用方法中写内部表名、字段名、项目名
- 示例使用占位符或脱敏车型
