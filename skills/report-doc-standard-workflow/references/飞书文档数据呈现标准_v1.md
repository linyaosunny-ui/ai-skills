# 协作平台文档数据呈现标准 v2（数据与呈现要求）

> 来源任务：待办工具 `6aca08548eb38a63f4ddae83`「创建协作平台文档需要有一个标准（数据要求）」（2026-10-10 创建 / 2026-10-12 定稿）
> 适用范围：一切带数据的协作平台文档（汇报、简报、专题分析、周报、配套文档）；人工产出与 AI 产出同样适用。
> 前置关系：本文件是 `report-doc-standard-workflow` 的配套标准，与该 skill 硬约束 7（口径位置）的边界见 §3。
> 状态：已补充呈现审核（2026-10-19）

---

## 0. 两条硬规则

1. **周期必须显眼**——文档中任何出现数据的部分，都要在紧邻位置写明数据时间段。
2. **周期全篇一致**——整篇文档从头到尾使用同一个数据周期；确需不一致，必须显式说明并由用户确认。

---

## 1. 规则一：周期写在哪（三个位置，第 1 项必做）

| 位置 | 要求 | 示例 |
|---|---|---|
| 文档开头 | 标题下方第一行独立写「数据周期」，加粗、不并入正文段落 | **数据周期：2026-08-01 ~ 2026-08-31** |
| 数据块下方 | 每张表 / 图 / 关键数字段落下方标注该块周期（可小字号，占一行） | 数据周期：2026-08-01 ~ 2026-08-31｜来源：内部数据平台 |
| 章节标题 | 各章节维度不同时，章节标题带周期 | 2.1 分战区开启量（2026-08-01 ~ 08-31） |

**不接受的写法**

1. 周期只在文末「附：数据口径说明」出现一次——读者看到中途的数字时并不知道窗口。
2. 写「近期 / 最新 / 本月 / 截至今日」等相对时间，不给具体起止日。
3. 只写月份不写起止日（如「8 月」）——统计窗口不是整月时（如 8/1~8/21）会直接误读。
4. 图表只给图例不给周期。

---

## 2. 规则二：周期全篇一致

1. **默认**：整篇同周期，所有数据块共用同一个窗口。
2. **允许不一致的唯一情形**：文档本身就是在做**跨周期对比**（如「7 月 vs 8 月」「上旬 vs 全月」）。此时：
   - **须事先经用户确认**（用户原话：「除非特别说明并且跟我确认过」）；
   - **开头必须写明对比关系**，例：**数据周期：2026-07-01~07-31 与 2026-08-01~08-31 对比**；
   - 每个周期都在各自数据块标注。
3. **禁止**：同一指标在文档不同位置用不同窗口却不说明。用户原话反例——「前半部分是 8 月 1 号到 30 号，后半部分是 8 月 1 号到 21 号，这样就很奇怪」。
4. **不得自行换窗口**：中途发现数据只到某天（如 8/21），要么把全篇统一到该窗口并说明，要么先问用户，不要前半全月、后半半月。

---

## 3. 与既有「口径放最后」规则的边界（消除冲突）

`report-doc-standard-workflow` 硬约束 7 原文：「数据来源 / 取数口径 / 数据周期一律放文档最后『附：数据口径说明』，不在正文前部堆口径（2026-09-17 用户明确）」。

本标准对两者做如下划分：

| 要素 | 位置 | 依据 |
|---|---|---|
| **数据周期（时间段）** | **显眼处**：文档开头固定行 + 各数据块下方 | 本标准规则一 |
| 数据来源 / 取数方法 / 表名 / 筛选条件 / 分子分母定义 | 文末「附：数据口径说明」 | 硬约束 7（2026-09-17） |

一句话：**周期要被看见，口径要被查得到**。
周期同时出现在文末口径说明里不违规，但文末**不是**它的唯一位置；反之，来源与方法类口径**不放**文档开头，避免正文前部堆口径。

---

## 4. 呈现形式硬规则（2026-10-19 新增）

> 目标：减少废话和长段落，让读者先看到结构、关系和重点。

### 4.1 三条硬规则

| 类型 | 必须做什么 | 不允许什么 |
|---|---|---|
| 表格优先 | 对比、并列事实、窗口结果、口径差异、行动清单，能转表格就转表格 | 用一大段文字解释本可用表格表达的并列信息 |
| 图形优先 | 流程、关系、构成、趋势、路径等适合图示的内容，必须画图呈现 | 明明适合图示却全部用文字；或把段落文字简单塞进图里 |
| 多形式呈现 | 关键结论、关键数字、必须被看见的判断，用加粗 / 高亮 / 引用块标出 | 重点埋在长段落里，让读者自己找结论 |

### 4.2 完成标准

三项处理完以后，才可进入交付确认。未达标时必须列出未达标项和原因，向用户确认“是否允许例外”；用户说“不行”就必须继续修改。只有用户明确同意的特殊情况可以例外。

## 5. 产出前自检（AI 与人工同一份清单）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 文档开头是否写了具体起止日期 | 标题下方有「数据周期：YYYY-MM-DD ~ YYYY-MM-DD」 |
| 2 | 每个数据块下方是否都有周期标注 | 表 / 图 / 关键数字段落逐块可对应到周期 |
| 3 | 全文周期去重后有几个 | 1 个；多于 1 个必须是 §2 的跨周期对比且开头已写明 |
| 4 | 是否出现不含具体日期的相对时间表述 | 无「近期 / 最新 / 本月 / 截至今日」单独出现 |
| 5 | 文末口径说明是否覆盖来源与取数方法 | 「附：数据口径说明」齐全 |
| 6 | 能表格化的内容是否已表格化 | 对比 / 并列事实 / 窗口结果 / 口径差异 / 行动清单已用表格呈现，或例外已经用户确认 |
| 7 | 能图示化的内容是否已图示化 | 流程 / 关系 / 构成 / 趋势 / 路径已用图呈现，图有补充价值且文字密度低，或例外已经用户确认 |
| 8 | 重点是否已标出 | 关键结论、关键数字、必须被看见的判断已加粗 / 高亮 / 引用块标出，或例外已经用户确认 |
| 9 | 是否已删除被表格或图替代的冗余文字 | 表格和图已表达的信息不再用长段落重复 |

机器检查（确定性检查，不依赖自觉）：

```bash
python3 <本skill>/scripts/check_doc_period.py <文档路径.md|.html|.txt>
# 批量扫目录时加 --skip-non-data 跳过「无日期区间且无『数据』字样」的文件
```

输出 `Pass` / `Fail` + 逐项明细，退出码 `0=通过`、`1=不通过`。

**适用范围**：只对带数据的文档运行（汇报 / 简报 / 专题分析 / 周报）。规范、流程、话术、清单类文档不必运行。
默认不跳过任何文件——宁可多报也不漏报；只有显式加 `--skip-non-data` 才按痕迹判定跳过。

检查项：A 是否标注了周期 / B 开头是否显眼标注 / C 全篇周期是否一致 / D 是否出现「近期·最新·本月」类模糊表述。

## 6. 模板片段（直接复制）

文档开头：

```
**数据周期：YYYY-MM-DD ~ YYYY-MM-DD**
（跨周期对比：**数据周期：YYYY-MM-DD~MM-DD 与 YYYY-MM-DD~MM-DD 对比**）
```

数据块下方：

```
数据周期：YYYY-MM-DD ~ YYYY-MM-DD｜来源：<数据源>
```
