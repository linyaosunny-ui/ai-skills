# 汇报文档标准流程 v1

> 用途：后续所有「汇报类文档」统一按本流程生产，保证结构、验证闸门、文件管理全工作站一致。
> 规范来源：待办工具任务「【skill和工作流：汇报文档】做报告的标准流程」（2026-08-28 负责人描述）。
> 配套 skill：`report-doc-standard-workflow`（已注册到 `{WORKSPACE}/AIAgents\skills\`，AI 触发后自动套用本流程）。

## 总原则

- **结论先行**：每份汇报先给核心结论，再给论据；S6 先由 `business-report-structure` 路由到分析型或决策版模板。
- **最小篇幅回答最大问题**：每步用「验证闸门」卡住——不过闸不进下一步。
- **问清楚再动手**：问题/假设不清晰时，先找负责人确认或请教专家，**不硬编**。
- **取数强约束**：凡涉及业务指标（开启量/创建量/成交量/各类率/分战区），走 `你的取数编排 skill` skill（本地 INDEX → DC → 内部数据平台 → BI 平台），先验本地再取数；某渠道失败须写明「具体渠道 + 具体原因」，禁写笼统「无权限」。
- **协作平台红线**：创建/发送协作平台文档（主文档、配套文档、评论）前必须负责人确认，AI 不自动发。

## 七步流程

### S1 背景（Background）
- **产出**：写进 `汇报大纲.md`
- **内容**：为什么做这份汇报、业务上下文、关键约束；按 `business-report-structure` 决策版模板的 WHY & WHY NOW 检查「现象→影响→根因」。
- **验证闸门**：背景是否说清了「为什么做、给谁看、要决策什么」？

### S2 最终要回答的问题（Questions）
- **产出**：写进 `汇报大纲.md`
- **内容**：列 1/2/3… 个最终问题（问题即汇报的验收标准）。多个问题要穷尽且互斥。
- **验证闸门**：问题是否清晰、可回答？不清晰 → 先确认，不进 S3。

### S3 假设（Hypotheses）
- **产出**：写进 `汇报大纲.md`
- **内容**：对 S2 每个问题给「预估答案」（假设），并标注朝哪个方向找证据；拿不准的标「待请教专家」。
- **验证闸门**：假设的回答，能否回答 S2 的最终问题？不能 → 回 S2/S3 修正。

### S4 数据 BRD（Data BRD）
- **产出**：独立 `数据BRD.md`
- **内容**：基于 S3 假设，列出验证所需数据：
  - 数据维度 + 最终 Excel 表头
  - 数据来源：哪张 SQL 表 / 哪些字段 / 表间互联关键字段（验证并确认）；非 SQL 的线下表，注明来源路径
  - 按 `business-report-structure` 决策版模板的 WHAT / HOW MUCH 要素核对：方案目标、核心原则、内外感知、方案内容、数据测算、推进计划；投入、产出、风险、边界、退出机制
- **验证闸门**：BRD 列出的数据，是否足以支撑 S3 假设的验证？缺维度 → 补 BRD。

### S5 Excel 产出（Delivery Data）
- **产出**：`产出数据/` 下的多 sheet Excel
- **内容**：一个主题一个 sheet；每个 sheet = 数据主题标题 + 该 sheet 核心结论 + 数据表（定稿后重点数字字段高亮，做得好标绿 / 不好标红；修订 / 待确认内容先标黄，黄色优先级更高）。
- **结构**：`产出数据/` 根放最终 Excel；`产出数据/过程数据/` 放原始/中间数据（CSV/JSON/XLSX）；`产出数据/Script/` 放取数脚本。
- **验证闸门**：Excel 是否给了 S4 BRD 要求的数据？是否足以支撑 S3 假设回答？不足 → 回 S4 补数。

### S6 大纲式报告（Outline Report）
- **产出**：`汇报.html`（根目录）+ `汇报大纲PPT`（根目录）+ 协作平台文档版（放汇报知识库）
- **结构**：走 `business-report-structure`
  - 背景 → 最终问题 → 核心假设 → 论据（小主题结论 + 对应数据 + 预估补图）
  - 总结（后续推进无要求可不写）
  - **backup**：放前面主题没用上的数据，按「小主题结论 + 论据」呈现，归到一个大 backup 节
  - **配套文档**：分析过程（协作平台文档形式，与主文档同放汇报知识库），供看细节
- **质量**：走 `business-report-structure` v3 的决策版模板
  - 开头写清决策点：是/否、A/B、金额、时间
  - 中间按 6 大原则组织：总分总、结论先行、MECE、定量定性、内部外部、一致性
  - 结尾回扣决策点：建议方案、预算上限、推进时间
  - 发出前跑 10 项 checklist，记录「质量检核结论」
- **呈现审核**：表格优先、图形优先、多形式重点标注；能表格化的内容用表格，适合图示的内容画图，关键结论和关键数字标出，并删除被表格 / 图替代的冗余文字。三项未达标时必须向用户确认是否允许例外；用户不同意就必须继续修改。
- **验证闸门**：结构完整？质量检核 10 项通过？若不通过 → 回修 S6，不进 S7。
- **建议**：
  - 同时产出 md 版 + 协作平台文档版 + html 版；html 版适合回头截图补充。
  - 文档来回交互用协作平台评论；针对评论改完，在评论回 `✅已修改`。

### S7 文件管理（File Management）
- **依据**：结合 `project-folder-init` skill，让每个汇报项目文件夹符合规范。
- **标准结构**：
  ```
  <汇报项目文件夹>/
  ├── 汇报大纲.md          # S1-S3 背景/问题/假设（唯一事实来源）
  ├── 数据BRD.md           # S4
  ├── 产出数据/            # S5
  │   ├── <最终>.xlsx      # 根：最终产出 Excel
  │   ├── 过程数据/        # 原始/中间数据
  │   └── Script/          # 取数脚本
  ├── set/                 # 配套汇报材料（图片/其他素材）
  ├── 汇报.html            # S6 HTML 版（根目录）
  ├── 汇报大纲PPT          # S6 PPT（根目录）
  └── 配套文档/            # S6 分析过程（协作平台文档形式，落汇报知识库）
  ```
- **原则**：每个模块（大纲/数据BRD/产出数据/报告/素材）都有对应管理位置，不乱放根目录。
- **会后复盘**：重要汇报结束后，按 `business-report-structure` 决策版模板的 +1 复盘法在文档后附会议记录，补 YES / NO / MORE 三类结论。

## AI 执行闸门（套用本流程时）

1. 读 S1-S3 → 若问题/假设不清，先停下一步、列「待确认清单」回负责人。
2. S4 BRD 写好 → 负责人确认表头/来源/拼表键后再取数。
3. S5 取数全程走 `你的取数编排 skill`；失败写具体渠道+原因，标「待取数回填」。
4. S6 产出 md/html；结构走 `business-report-structure`，由 `business-report-structure` 路由模板；决策型跑 11+1 checklist；协作平台文档创建/发送前必须负责人确认。
5. 每步写回「验证结论」，不过闸不进下一阶段。
