# report-doc-standard-workflow - 汇报文档标准生产流程

**版本**: 1.5
**标准底稿（人类可读，必读）**: `references\汇报文档标准流程_v1.md`
**数据呈现标准**: `references\协作平台文档数据呈现标准_v1.md`（数据周期与呈现要求，硬约束 11 / 12 的正文）

## 使用场景

- 业务汇报 / 分析报告 / 周报 / 专题汇报：从背景、假设到报告成品的完整流程
- 创建或发布任何含表格/数字/统计周期的协作平台文档（强制触发，哪怕不是传统汇报）
- 效果评估、阶段复盘、双周报、数据看板说明
- 三种模式按用途选：简单模式（只整理）/ 飞阅版（给别人看）/ 讲解预演版（自己要讲）

## 实战案例

一份「阶段效果评估」的完整走法：S1 背景（给谁看、要回答什么）→ S2 问题 → S3 假设 → S4 数据 BRD → S5 Excel 产出 → S6 大纲式报告（先路由汇报类型，再按模板检核 + 呈现审核）→ S7 文件归位。

两个易错点：① 每步有验证闸门，不通过不进下一步；② 含数据文档发布前必跑 `check_doc_period.py` 且通过，统计周期全文一致。

## 七步流程（每步带验证闸门，不过闸不进下一步）

> **S0（前置·必做）实践库检索**：动手写第一个字之前，先读 `{WORKSPACE}/Knowledge/practice/index/practice-index.json`，按本次任务类型匹配触发词，读命中的实践卡（≤5 张），**照卡里的做法执行、闸门逐条勾**。含数据的文档，`P-004 协作平台文档周期一致性` 视为强制卡。没命中也照常开工，做完按 S7 回流。
> 规则与卡清单见 `practice-library` skill 与 `Knowledge/practice/README.md`。

| # | 阶段 | 产出物 | 验证闸门 |
|---|------|--------|---------|
| S0 | 实践库检索 | （无产出物，读卡） | 已读索引并匹配；命中的卡闸门全部勾过 |
| S1 | 背景 | `汇报大纲.md` | 是否说清为什么做/给谁看/要决策什么 |
| S2 | 最终要回答的问题 | `汇报大纲.md` | 问题清晰、可回答？否→先确认 |
| S3 | 假设 | `汇报大纲.md` | 假设能否回答 S2 问题？否→回修 |
| S4 | 数据 BRD | `数据BRD.md` | BRD 数据能否支撑 S3 假设？缺→补 |
| S5 | Excel 产出 | `产出数据/*.xlsx` | 是否覆盖 BRD、支撑假设？否→回补数 |
| **S5.5** | **讲解逻辑对齐**（仅 C 讲解预演版走；B 飞阅版跳过） | `讲解逻辑.md` + `材料台.md` | 材料台是否把证据与信息平铺齐全？用户是否已自述一遍并把讲述顺序讲清？否→不回下一步 |
| S6 | 大纲式报告 | `汇报.html` + `汇报大纲PPT` + 协作平台版 | 走 `business-report-structure`：先路由汇报类型，再按分析型 / 决策版模板检核；同时通过表格 / 图 / 重点标注呈现审核 |
| S7 | 文件管理 | 项目文件夹 | 各模块落位合规（见下结构） |

## 标准文件夹结构

```
<汇报项目文件夹>/
├── 汇报大纲.md          # S1-S3
├── 数据BRD.md           # S4
├── 产出数据/            # S5
│   ├── <最终>.xlsx
│   ├── 过程数据/
│   └── Script/
├── set/                 # 配套素材（图片等）
├── 汇报.html            # S6
├── 汇报大纲PPT          # S6
└── 配套文档/            # S6 分析过程（协作平台文档，落汇报知识库）
```

## S5.5 讲解逻辑对齐（C 讲解预演版专用）

> **为什么要有这一步**：B 飞阅版是给别人看的，读者自己看，结构合理就行；C 讲解预演版是**自己要讲**，结构必须贴合**你的讲述顺序**——哪件事先讲、哪个是重点、哪条论据挂在哪个结论下面。这一步不做，写出来的文档逻辑是"文档的逻辑"，不是"你讲出来的逻辑"。

### 三步

1. **出材料台（AI 做）**：把这一轮所有证据和内容**平铺罗列**成 `材料台.md` —— 不做取舍、不做排序，一条一条列清楚（事实 / 数字 / 引语 / 出处）。
2. **模拟讲述（用户做，AI 记录）**：用户对着材料台**自述模拟讲解**一遍。AI 记录四件事：
   - **讲述顺序**：先讲什么、后讲什么；
   - **重点标记**：哪几条是必须被记住的；
   - **论据挂载**：哪条证据是给哪个结论撑腰的；
   - **取舍**：哪些只是背景、当场可以不讲。
   产出 `讲解逻辑.md`。
3. **闸门**：用户确认讲法后，才进 S6。

### 与 S6 的衔接

- S6 按 `讲解逻辑.md` **重排文档结构**，不再套模板骨架（决策版/分析型的骨架只用于检查有没有漏项，不用于定顺序）；
- 配图**依据讲解逻辑**（哪一步需要图辅助讲清楚），不是依据文档目录；
- 仍保留 QA 形式与关键结论高亮——**讲解预演版要能"看着直接讲"**。

### 产出

C 模式出**两篇**：

| 篇目 | 用途 | 形态 |
|---|---|---|
| `讲解预演版` | 自己看+讲，定讲法 | 材料台 + 讲解逻辑 + 按逻辑排的 QA 文档（含图） |
| `讲解正式版` | 讲法定了之后定稿 | 基于讲解逻辑重排的正式版，对外可用 |

### 不使用

- **B 飞阅版**：不给自己讲，跳过 S5.5，直接 S6；
- **A 简单模式**：不跑本流程，走「定库 → de-ai-ify → lark-doc」；
- 纯取数、不产出文档的场景不跑。

## AI 执行硬约束

1. **确认优先**：S2/S3 问题或假设不清 → 列「待确认清单」回用户，不硬编。
2. **取数走 skill**：凡业务指标（开启/创建/成交/各类率/分战区），必走 `你的取数编排 skill`（本地 INDEX→DC→内部数据平台→BI 平台）；失败写「具体渠道+具体原因」，禁笼统「无权限」。
3. **协作平台红线**：创建/发送协作平台文档（主/配套/评论）前必须用户确认，AI 不自动发。
4. **写回验证结论**：每步写「验证结论」，不过闸不进下一阶段。
5. **多形态产出**：S6 同时出 md + html（+ 协作平台版待确认）；html 适合截图补充；评论改完回 `✅已修改`。主文档与配套文档均落「汇报」知识库（创建/发送前用户确认）。
6. **区分三模式**（2026-11-13 新增）：A 简单模式（只整理，会议纪要类）/ B 完整模式·飞阅版（给别人看，跳过 S5.5）/ C 完整模式·讲解预演版（自己要讲，必走 S5.5，出两篇）。判定依据见 AGENTS.md「强制调用规则」第 5 条；无法判定先问用户。
7. **数据口径放最后**：数据来源 / 取数口径 / 数据周期一律放文档最后「附：数据口径说明」，不在正文前部堆口径（与 `business-report-structure` 一致）。（2026-09-17 用户明确）
8. **取数明细先确认**：数据类分析取数完成后，必须先将 100 条明细导出 CSV 呈用户确认（含关键字段：ID/车型/时间/分类等），确认无误后才可继续写报告/分析；多车型/多维度对比时分子分母口径全篇统一。（原属 business-report-structure 的流程闸门，2026-09-17 移入）
9. **不写"局限"章节**：汇报文档不出现"局限 / 研究局限 / 数据局限"类自我设限章节；确需提示的风险融入正文对应结论处一句话说明。（2026-09-17 用户明确：以后都不要再出现）
10. **假设迭代循环**：S5 数据验证过程中若发现新假设或数据推翻原假设 → 回写 `汇报大纲.md`「核心假设」清单（每条标注来源：用户初始 / 数据发现；状态：待验证 / 已验证 / 被推翻）→ 补数据BRD → 再取数验证 → 循环，直到无新假设或用户叫停。每轮循环写验证结论。（2026-09-17 用户明确的工作模式：用户给分析与基础假设，agent 基于假设分析、通过数据发现新假设、持续迭代）
11. **数据周期必须显眼且全篇一致**（2026-10-12 新增，与 #7 的边界见标准 §3）：
   - 文档开头标题下方固定一行「**数据周期：YYYY-MM-DD ~ YYYY-MM-DD**」；每个数据块（表 / 图 / 关键数字段）下方另标一次。
   - 全篇周期必须一致；仅在做跨周期对比时允许出现多个周期，且**开头必须写明对比关系**；不得前半全月、后半半月。
   - 禁止只写「近期 / 最新 / 本月」或只写月份不写起止日。
   - **与 #7 的边界**：「周期」要被看见（放显眼处），「来源 / 取数方法 / 筛选条件 / 分子分母定义」仍放文末「附：数据口径说明」。
   - 正文：`references\协作平台文档数据呈现标准_v1.md`；交付前跑机器检查：`python3 scripts\check_doc_period.py <文档路径>`（退出码 0=通过）。
12. **呈现质量硬闸门**（2026-10-19 新增）：
   - **表格优先**：对比、并列事实、窗口结果、口径差异、行动清单，能转表格就转表格；不得用长段落反复解释表格能表达的信息。
   - **图形优先**：流程、关系、构成、趋势、路径等适合图示的内容，必须调用画图能力呈现；图要补充关系和变化，不能把段落文字塞进图里。
   - **多形式呈现**：关键结论、关键数字、必须被看见的判断，要用加粗 / 高亮 / 引用块等标出；不要让重点埋在长段落里。
   - **先完成再交付**：以上三项都是 S6 审核项。任何一项未达标，都不能称为“完成”；必须向用户说明未达标项和原因，由用户确认是否放宽。用户说“不行”就必须继续修改；只有用户明确同意的特殊情况可以例外。

## 结构检核脚本

S7 归位前运行结构检核（确定性检查，不依赖 AI 自觉）：

```powershell
powershell -File <本skill>\scripts\check_report_project.ps1 -ProjectDir "<汇报项目文件夹>"
```

输出 Success/Fail 清单 + 退出码（0=通过）。检查项：汇报大纲.md 三节齐全且无残留占位符、数据BRD.md 存在、产出数据（最终 xlsx + 过程数据 + Script）、set / 配套文档目录、汇报.html（S6 后提醒级）。

## 执行步骤

0. **S0 实践库检索**：读 `{WORKSPACE}/Knowledge/practice/index/practice-index.json` → 匹配触发词 → 读命中的卡（≤5 张）→ 卡里的闸门逐条勾。命中口径 / 假跌 / 小样本 / 周期一致性类卡时，直接按卡执行。做完本流程后在 S7 回流（见下）。
1. 建 `<汇报项目文件夹>`：落位在项目本身的文件夹（默认 `{WORKSPACE}/1、项目/<项目名>/`，与 `project-folder-init` 通用项目一致，一个事情一个文件夹），用其「汇报项目文件夹」变体模板生成 汇报大纲.md / 数据BRD.md / 产出数据 / set / 配套文档 骨架。
2. 跑 S1-S3，写 `汇报大纲.md`；不清晰先确认。
3. 写 `数据BRD.md`（S4），用户确认表头/来源/拼表键。
4. 走 `你的取数编排 skill` 取数 → `产出数据/`（S5），写验证结论。Excel 一个主题一个 sheet，每 sheet 呈现：主题标题 + 该主题核心结论 + 数据表；重点数字字段高亮（做的好标绿、不好标红）。
   - **修订期统一黄色，定稿后再上业务语义色**：本轮新增 / 修改 / 待确认内容一律标黄；黄色优先级高于绿色和红色，同一处不叠加其他颜色。用户确认后，取消黄色；若仍是重点或业务表现好 / 差，再改为绿色 / 红色。
5. 出 `汇报.html` + `汇报大纲PPT` + 协作平台版草稿（S6）：先按硬约束 11 完成表格化、图示化和重点标注，再走 `business-report-structure` 判断分析型 / 决策型模板；分析型跑结构自检，决策型跑 11+1 checklist，并记录「质量检核结论」与「呈现审核结论」，再交用户确认；协作平台发送前确认。
6. 归位文件（S7），先跑 `scripts\check_report_project.ps1` 结构检核，通过后创建两个快捷方式索引，再回报路径与下一步：
   - `{WORKSPACE}/汇报文档/<项目名>.lnk` → 指向项目文件夹（汇报索引，目录不存在则先创建）
   - `{WORKSPACE}/data/汇报数据沉淀/<项目名>产出数据.lnk` → 指向 `<项目文件夹>\产出数据`（数据沉淀，目录不存在则先创建）
   - 快捷方式用 PowerShell `WScript.Shell` COM 创建；已存在同名 .lnk 则更新目标不重复建。

## S7 回流（实践库）

归位完成后判断本次是否产生了「重复 ≥2 次 + 可复用 + 可校验」的做法：

- 是 → 调 `practice-library`：新做法建新卡，已有卡的补充 / 反例更新原卡
- 否 → 不建卡（事实与数字仍走 wiki / Memory 沉淀）

## 注意事项

- 分工：本 skill 管从背景到交付的全链路 + 文件管理；`business-report-structure` 管 S6 大纲结构；`business-report-structure` 管 S6 模板路由与质量检核（v3 已合并决策版框架）。
- `汇报大纲.md` 是唯一事实来源，改状态只改它。
